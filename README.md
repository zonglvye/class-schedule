# 我的课表 · 作业待办 · 定时提醒

一个装进手机桌面的**课表 + 作业待办**小应用。纯前端 PWA，**不需要服务器、不需要账号、不联网**，所有数据只存在你自己手机的浏览器里。

- 主界面：周课表（左滑右滑切周）+ 今日日程 + 作业清单 + 设置
- 已实现：**单双周 / 周次范围 / 自定义周次**、上课地点、任课老师、多时间段、**作业 DDL 倒计时与优先级与完成度**、**课前与作业截止定时提醒**、**深色模式**、**添加到手机桌面（独立图标）**、离线可用、导出导入备份

---

## 一、最快用法（30 秒）

**方式 A：双击 `index.html`** —— 立刻能用（课表、作业、倒计时、深色模式全都能用）。
局限：`file://` 打开时浏览器不允许申请"系统通知"权限，所以到点只能看 App 内横幅（需页面开着）。

**方式 B：双击 `启动（电脑预览）.cmd`** —— 自动打开本地服务器并弹出浏览器。
手机连同一个 WiFi，访问它显示的 `http://本机IP:4173/`，就能在手机上用了。

**方式 C：手机安装（推荐，提醒最可靠）** —— 见下面第二节。

**Cloudflare 临时隧道**（免账号备用方案）：双击 `启动（临时公网地址）.cmd`，它会起本地服务器 + 建隧道，并把 `https://xxxx.trycloudflare.com` 地址打印出来。这是 [Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)，官方明确说明**无可用性保证**，且**关掉窗口地址即失效**，下次重开换新地址。

#### 樱花 FRP 配置要点（如果你想走这条）

依据[官方文档](https://doc.natfrp.com/faq/site-inaccessible.html)的"建站条件"表：

| 节点类型 | HTTP(S) 隧道 | TCP 隧道映射 HTTP |
|---|---|---|
| **海外节点** | **需实名认证**（不需备案）✅ | 需实名认证 |
| 其他节点（国内） | 需实名认证 **+ ICP 备案** ❌ | ×（需配置自动 HTTPS） |

免费「普通用户」额度：**隧道限速 10 Mibps、隧道 2 条、每月 5 GiB 流量**（每日签到可拿免费流量）。对本 App 足够——整站才 110 KB，5 GiB 约等于 4 万多次访问。

具体步骤：

1. 注册樱花账号 → 管理面板完成**实名认证**（¥1，走支付宝刷脸）
2. 准备一个**自己的域名**（`.top` / `.xyz` 一年十几块），在域名商处把子域名 CNAME 到樱花给的节点地址
3. 面板新建**隧道类型 = HTTP(S)**，绑定该域名，本地地址填 `127.0.0.1`、本地端口填 **4174**
4. 节点务必选**海外节点**
5. 下载樱花启动器（或 frpc），启动隧道；然后访问 `https://你的域名/`
6. 记得先起本地服务器：`node _dev/serve.mjs 4174`

⚠️ 樱花**不提供域名、也不代备案**，实名认证必须你本人刷脸完成——这两步需要你自己做。

```powershell

git commit -m "更新"
git push            # 需要时用令牌认证；第一次可用下面这种一次性方式
git push "https://<用户名>:<令牌>@github.com/<用户名>/<仓库名>.git" main:main
```

然后仓库 Settings → Pages → Source 选 `Deploy from a branch` → Branch 选 `main` + `/ (root)` → Save，1~2 分钟生效。

#### ⚠️ 本机网络情况：`github.com:443` 连不上

实测本机 **`github.com` 的 443 端口不通**（DNS 能解析、`api.github.com` 和 Pages 站点都正常），所以 `git push` / `git fetch` 会超时失败。替代方案是用 GitHub API 直接推送：

```powershell
# 会先用本地 git 生成提交，再把对象传到 api.github.com，最后更新 ref
powershell -ExecutionPolicy Bypass -File _dev/push-via-api.ps1 -Token <令牌>
# 想顺手提交当前改动，加 -Message：
powershell -ExecutionPolicy Bypass -File _dev/push-via-api.ps1 -Token <令牌> -Message "更新说明"
```

脚本要点：
- 提交对象仍由**本地 git** 生成，所以哈希可复现；它会检查"本地树的哈希 == 重建出的树哈希"，不一致就直接中止，不会写坏仓库。
- 需要本地 HEAD 的父提交与远端一致（可快进），脚本会自动检查并提示。
- 只接受 `-Token` 参数，**不会把令牌写进任何文件**。

> 网络恢复后（比如挂了代理），直接用 `git push` 也行——本地仓库是标准的 git 仓库。

## 三、定时提醒是怎么工作的（重要，请一定读）

这个 App 是**网页应用**，它的提醒能力受浏览器规则限制，所以我用了四层设计，尽量不漏：

| 层级 | 触发条件 | 效果 |
|---|---|---|
| ① 系统通知 | 页面在后台/前台运行，且已授权通知 | 手机通知栏弹出「还有 15 分钟上课 · 高等数学」 |
| ② App 内横幅 | 页面开着 | 顶部弹出色块横幅，20 秒后自动收起 |
| ③ 声音 + 震动 | 同上（可在设置里关） | 两短一长的提示音；支持的手机同时震动 |
| ④ 错过补偿 | 重新打开 App 时 | 检查刚刚错过的提醒，横幅汇总告诉你「刚才有 N 条提醒没能弹出」 |

**关于"到点"的精确语义**（这块我特意做得比一般课表 App 更宽容）：
- 上课提醒：从「课前 N 分钟」一直提醒到**这节课正式开始**为止。即使你课前 3 分钟才打开 App，也会立刻看到「还有 3 分钟上课」，不会因为错过了那个瞬间就静默失效。
- 作业提醒：你可以在设置里多选提醒点（提前 1 天 / 3 小时 / 30 分钟……）。每个提醒点各自触发一次，到截止时刻为止都算数。
- 逾期兜底：作业已经过了截止时间、且你打开 App 时（6 小时内），额外提醒一次。
- 去重：每次提醒都会记一条流水，同一节课/同一个提醒点**只响一次**，不会重复轰炸。

**⚠️ 网页应用的天然限制**：浏览器不允许网页在完全关闭后自己启动。所以：
- 想稳定收到提醒，请**从主屏幕图标打开**，并尽量让它在后台保活（安卓可以给浏览器/添加到桌面的应用"允许后台运行"和"关闭电池优化"；iOS 后台保活更严格，建议配合下一条）。
- **想要 100% 可靠 → 用「导出到系统日历」**：设置页 → 导出到系统日历，会生成一个 `.ics` 文件。用手机打开它并导入系统日历后，**由系统闹钟负责提醒**，跟你开不开 App 完全无关。课程事件带「提前 N 分钟」闹钟，作业按你选的每个提醒点各生成一次。这是最稳的兜底方案，强烈建议每学期导一次。

## 四、功能一览

**课表**
- 周视图，随教学周自动对齐；左右滑动切周，点周次标签可跳到任意一周；「本周」一键回位
- 课程支持：名称、任课老师、上课地点、颜色、**多个时间段**（如周一 1-2 节 + 周三 3-4 节）
- 周次：**每周 / 单周 / 双周 / 自定义（点选任意周组合）**，可设起始与结束周
- 今天所在的列和格会自动高亮；正在上的课有「上课中」标记和描边
- 点空格 = 直接新建课程（自动预填星期与节次）；点课程 = 编辑；点右上 + 也能加

**日程**
- 今日课程（含"还有 X 分钟上课 / 还剩 X 分钟下课"倒计时）
- **接下来的提醒**：列出未来每条提醒的具体时刻，可对着核对
- 最近截止的作业、未来 7 天课程

**作业**
- 内容、关联课程、截止日期+时间、**优先级（紧急/重要/普通）**、**完成度进度条**、备注
- **DDL 倒计时**（秒级刷新，逾期变红，24 小时内变橙）
- 筛选：待完成 / 今天到期 / 7 天内 / 已完成 / 全部；排序：截止时间 / 优先级 / 课程 / 添加时间
- 每项作业可单独设提醒点；勾选圆圈一键完成

**设置**
- 学期：开学第一周的周一（自动算出"现在是第几周"）、学期总周数
- 上课时间：每节的上下课时间可改，可增删节次，影响课表与提醒
- 提醒：课前提前几分钟、作业提醒点（多选）、逾期兜底、声音、震动、开启/关闭系统通知、发送测试提醒
- 外观：自动 / 浅色 / **深色**
- 数据：导出备份（JSON）、导入备份、**导出到系统日历（ICS）**、导出作业（CSV）、分享/安装引导、清空数据
- 首次打开会有 3 步新手引导（学期 → 上下课时间 → 开启提醒）

## 七、常见问题

**Q：加了课程但课表上没看到？**
A：多半是周次。检查①「设置 → 学期」里的开学第一周的周一是否正确（它决定"现在是第几周"）；②这门课设的是单周还是双周、起止周是多少。用周次标签跳到对应周看看；或直接把这门课设成"每周 + 第 1-20 周"先验证。

**Q：到点没提醒？**
依次检查：
1. 设置页顶部有没有「✅ 系统通知已开启」；是 🚫 就点浏览器地址栏的锁形图标 → 通知 → 允许，然后刷新
2. 上课提醒 / 作业截止提醒的开关有没有打开（设置 → 提醒）
3. 作业那一项有没有勾选提醒点（不勾就只会在"逾期兜底"时提醒）
4. 是否用 `file://` 直接打开的？换成本地服务器或 HTTPS 地址
5. 想彻底稳 → 用「导出到系统日历」，交给系统闹钟
6. 可以点「发送测试提醒」验证链路是否通

**Q：为什么提醒时间和我设的差一两分钟？**
A：节次时间只精确到分钟（比如 08:00），提醒点按"上课时刻 − 提前量"计算，是正常误差。若勾了"提前 15 分钟"而你在课前 5 分钟才打开 App，它会按"还有 5 分钟上课"提示。

**Q：能多个手机同步吗？**
A：不能，数据是纯本地的。同一台手机的浏览器 + 桌面图标共享数据（同源）；用导出/导入 JSON 可以在设备间搬。

**Q：iPad / 电脑上能用吗？**
A：能，同一份代码自适应，宽屏下课表会自动变大，支持左右方向键切周、Esc 关闭弹窗。

## 九、已知限制（如实说明）

1. **网页无法在完全关闭后自启动**：这是浏览器的硬限制，不是 bug。**已由 Android APK 客户端解决**（见第十节）；纯网页环境仍建议用 ICS 导入系统日历兜底。
2. **iOS 后台保活严格**：即使添加到主屏幕，长时间不打开仍可能收不到通知；iOS 16.4 以下不支持网页通知。
3. **`file://` 直接打开**：没有系统通知、没有"添加到桌面"，其余功能正常。
4. **节次时间精确到分钟**：提醒点按分钟计算。
5. **数据不跨设备同步**：纯本地存储，靠导出/导入 JSON 迁移。
6. **调课/临时停课**：目前靠"改周次范围"或"自定义周次"跳过，没有单独的"某周某天停课"开关。
7. **导出到系统日历需要手动导入**：iOS 点开 .ics 文件选择"添加到日历"，安卓用系统日历打开该文件；网页无法静默写入系统日历。

## 十、Android APK 客户端（提醒最可靠的做法）

网页版有个改不掉的先天限制：**页面一关，提醒就没了**。APK 版就是来解决这件事的 ——
它把提醒从"页面开着才响"升级成**系统级闹钟：关掉 App、息屏、甚至重启手机后照样响**。

### 10.1 拿到安装包

| 方式 | 做法 | 适合 |
|---|---|---|
| **A. 手机直接下载** | 手机浏览器打开 `https://zonglvye.github.io/class-schedule/apk/class-schedule.apk` | 最快，改完代码云端自动出新包 |
| **B. 本机编译** | `powershell -ExecutionPolicy Bypass -File _dev\build-apk-local.ps1` | 想出包立刻拿到、或没配 CI |

本机出包位置：`D:\dhs\apk-输出\我的课表-v1.0.0.apk`（约 166 KB）。
安装时系统会提示"未知来源应用"，允许即可（自签名应用，未上架任何商店）。

### 10.2 和网页版的区别

| | 网页版 PWA | APK 客户端 |
|---|---|---|
| 提醒可靠性 | 页面开着才响 | **系统闹钟，关掉 App / 息屏 / 重启后都响** |
| 离线 | Service Worker 缓存 | 资源全部内置，**完全不依赖网络** |
| 依赖域名 | 需能访问 github.io | 不需要 |
| 通知按钮 | ❌ | 「知道了」「稍后 10 分钟」 |
| 数据位置 | 浏览器 localStorage | 应用私有存储（**与网页版互相独立**） |
| 安装包体积 | — | 约 166 KB，零第三方依赖 |

### 10.3 装好后必做三步（不做的话到点真的不响）

App 内 → **设置 → 提醒**，页面上会直接显示还差哪一项，点按钮逐项开：

1. **允许通知**（Android 13+ 需运行时授权）
2. **允许精确闹钟**（Android 12+，`SCHEDULE_EXACT_ALARM`）
3. **关闭电池优化**

**国产 ROM 还要多做一步**（关键，缺了照样不响）：
手机管家 / 设置 → 应用管理 → 我的课表 → 允许**自启动**、允许**后台运行**、电池策略设为**不受限制**。
华为、小米、OPPO、vivo 都会在后台把闹钟掐掉，各家菜单名不同但都有这几项。

### 10.3.1 两分钟自己验证「关掉 App 也会响」🧪

这一步是网页版永远做不到、也是这个 APK 存在理由的**唯一硬指标**，值得亲测一次：

1. 设置 → 提醒 → 点 **「60 秒后测试系统闹钟」**
2. **立刻把 App 切到后台或直接上滑关掉**（关键，别停在当前页面）
3. 等 60 秒 —— 弹出「测试提醒 · 我的课表」就说明整条链路通了

如果没响，按顺序查：通知权限 → 精确闹钟 → 电池优化 → 国产 ROM 自启动（见 10.3）。
还是不行就点 **「复制诊断信息」**，把内容发出来，一眼就能看出卡在哪一环。

### 10.4 数据怎么从网页版搬过来

两边数据**互相独立**（浏览器和 App 各存一份），迁移走备份文件：

1. 网页版 → 设置 → 数据与备份 → **导出备份 (JSON)**
2. 把 json 传到手机（微信文件传输助手 / QQ / 数据线都行）
3. APK → 设置 → 数据与备份 → **导入备份** → 选中它

反向同理。**当前版本不带任何预置课表**（仓库里不再包含个人数据），首次安装会走新手引导，让你自己录课表；
如果你之前在旧版里导出过备份 JSON，用「导入备份」即可一键恢复。

> APK 里点「导出备份」会直接写进手机 **「下载/我的课表/」** 目录。
> 因为 Android WebView 里网页那种"下载链接"是**静默失效**的（点下去毫无反应），所以 APK 版走了原生保存通道。

### 10.5 技术实现（想改代码的人看这里）

```
android/                              自研 WebView 壳：不用 Kotlin、不用 AndroidX、零第三方依赖
  app/src/main/java/io/github/zonglvye/classschedule/
    MainActivity.java                 全屏 WebView；拦截 https://app.local/ 从 assets 取资源
    WebAppBridge.java                 暴露为 JS 的 window.CSApp（分工：前端算，原生响）
    ReminderScheduler.java            AlarmManager 精确闹钟（setExactAndAllowWhileIdle）
    ReminderReceiver.java             到点弹通知；App 在前台则不重复打扰；支持稍后提醒
    BootReceiver.java                 开机 / 应用更新后自动重排闹钟（不做这步重启就全丢）
    Notify.java                       4 个通知渠道（上课/作业 × 响铃/静音）
    FileExporter.java                 导出走原生存进系统「下载」目录
    Reminders.java                    提醒点索引持久化（SharedPreferences）
  app/src/main/assets/www/            构建时由 _dev/build-apk-web.mjs 拷入（不进版本库）
  app/src/test/java/...               原生层单元测试（Robolectric，JVM 上跑，不需要真机）
.github/workflows/build-apk.yml       云端构建：runner 自带 Android SDK，先跑单元测试再打包
_dev/build-apk-local.ps1              本机构建脚本
_dev/build-apk-web.mjs                把单文件网页装进 APK（并校验应用代码在不在）
_dev/test-native.mjs                  桥接层自检：74 项断言，无需手机
_dev/native-ui-check.cjs              真实浏览器里的 APK 模式 UI 检查：48 项断言
```

**核心设计：前端只负责算「什么时候该提醒什么」，原生只负责「到点弹通知」。**
课表、单双周、作业 DDL 那套算法只存在一份（还是 `assets/app.js` 里那一份），
所以网页版和 APK **永远不会算出两套结果**。

一次同步会把**整个学期剩下的提醒点**都交给系统闹钟（上限 400 条，`AlarmManager` 单应用上限约 500），
所以即使几周不开 App，闹钟也不会断档；开机后 `BootReceiver` 会按持久化索引自动重排。

### 10.5.1 这些功能是怎么验证的（四层，共 212 项断言）

| 层 | 命令 | 断言 | 覆盖什么 |
|---|---|---|---|
| 网页版逻辑 | `node _dev/test-logic.mjs` | 43 | 周次推算、单双周、提醒触发与去重、导出 |
| 桥接层契约 | `node _dev/test-native.mjs` | 74 | 前端算出的提醒点、单双周在原生排程里也对、导出改走原生、去重合并、测试闹钟与诊断信息 |
| 真实浏览器 UI | `node _dev/native-ui-check.cjs` | 48 | 无头 Edge 里跑 APK 模式：设置页渲染、返回键链路（含首启向导弹层）、测试闹钟入口、零 JS 错误 |
| 原生 Java | `cd android && ./gradlew testDebugUnitTest` | 47 | 闹钟排程/上限/降级、通知渠道与按钮、开机重排、测试闹钟、导出落盘、桥接入参容错 |

原生层测试用 Robolectric 在 JVM 上**真跑**（不是 mock）：`ShadowAlarmManager` 能看到真的排了几条闹钟、
`ShadowNotificationManager` 能读到通知内容与渠道、`ShadowWebView` 能验证入口 URL 与返回键转发。
CI 在打包前先跑这一层 —— 所以**原生代码改坏了，云端构建会直接变红**。
（这些测试依赖是 `testImplementation`，不会打进 APK：已验证 dex 里 `Landroidx/` 出现 0 次。）

### 10.6 权限与隐私

声明了这些权限，用途都写在括号里：`POST_NOTIFICATIONS`（弹提醒）、`SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`（准时）、
`RECEIVE_BOOT_COMPLETED`（重启后重排闹钟）、`VIBRATE`、`WAKE_LOCK`、
`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（引导关电池优化）、`WRITE_EXTERNAL_STORAGE`（仅 Android 9 以下导出用，`maxSdkVersion=28`）、
`INTERNET`（备用，当前所有资源都在本地，不发任何网络请求）。

**没有账号、没有服务器、没有任何数据上传。**

### 10.7 提醒不响怎么排查

1. 设置页顶部那行状态是不是 ✅？缺哪项点哪个按钮。
2. 点「发送测试提醒」——看不到就是通知权限问题。
3. 点「立即重排闹钟」——会显示当前排了多少条（正常是几十到几百条）。
4. 检查国产 ROM 的自启动 / 后台运行 / 电池策略（10.3 最后一段）。
5. 华为/小米还可在「设置 → 通知 → 我的课表」里确认对应渠道没被静音：
   有 4 个渠道（上课提醒·响铃 / 上课提醒·静音 / 作业截止提醒·响铃 / 作业截止提醒·静音）。
6. 实在不行就用兜底方案：设置 → 数据与备份 → **导出到系统日历**，让系统日历负责响。
